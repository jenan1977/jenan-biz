# Jenan-Biz Backend Worker

## Overview

This document describes how to run the FastAPI backend + background worker and how to use the Agents API endpoints.

---

## Prerequisites

- Python 3.11+
- PostgreSQL (running and accessible via `DATABASE_URL`)
- All Python dependencies installed:

```bash
pip install -r backend/requirements.txt
```

---

## Environment Variables

Copy `backend/.env.example` to `backend/.env` and fill in the values:

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | `postgresql://postgres:postgres@localhost:5432/jenan_biz` | PostgreSQL connection string |
| `DATABASE_ECHO` | `False` | Log all SQL statements |
| `ALLOWED_ORIGINS` | *(empty)* | Comma-separated CORS origins, e.g. `http://localhost:3000` |
| `WORKER_POLL_INTERVAL` | `5` | Seconds between queue polls when empty |

---

## Quick Start (Development)

Run the backend and worker together with a single command:

```bash
./scripts/run_dev_backend_and_worker.sh
```

This script will:
1. Run `startup()` once (validates config, checks DB, creates tables).
2. Start the background worker (`app.worker.run`).
3. Start the FastAPI server via `uvicorn` on port 8000.

Then open:
- Analytics UI: http://localhost:8000/analytics.html
- Swagger docs: http://localhost:8000/docs

---

## Manual Start

### Backend only

```bash
PYTHONPATH=backend uvicorn app.asgi:app --reload --port 8000
```

### Worker only

```bash
PYTHONPATH=backend python -m app.worker.run
```

## Agents API Endpoints

All endpoints are prefixed with `/api/v1/agents`.

> **Authentication**: JWT auth (roles: `admin`, `manager`, `accountant`) will be enforced once the JWT deps PR is merged. Until then, a development stub is active.

### POST `/api/v1/agents/analyze`

Enqueue a financial analysis job.

**Request body** (all fields optional):
```json
{
  "date_from": "2025-01-01",
  "date_to":   "2025-12-31",
  "company_id": "<uuid>"
}
```

**Response** `202 Accepted`:
```json
{ "job_id": "<uuid>", "status": "pending" }
```

---

### POST `/api/v1/agents/report`

Enqueue a PDF report generation job (same payload as `/analyze`).

---

### POST `/api/v1/agents/inventory/bulk-update`

Enqueue a bulk inventory update job.

**Request body**:
```json
{
  "updates": [
    {
      "inventory_id": "<uuid>",
      "quantity_delta": "10.00",
      "reason": "stock received"
    }
  ]
}
```

`quantity_delta` is a decimal string. Positive = add stock, negative = remove.

---

### GET `/api/v1/agents/jobs/{job_id}`

Poll the status and result of any job.

**Response**:
```json
{
  "job_id": "<uuid>",
  "job_type": "financial_analysis",
  "status": "succeeded",
  "attempts": 1,
  "result": { ... },
  "error": null
}
```

---

### GET `/api/v1/agents/jobs/{job_id}/download`

Download the PDF generated by a `pdf_report` job.  
Returns the file as `application/pdf` with `Content-Disposition: attachment`.

Only available when `status = succeeded`.

---

## Job Queue

The queue is a PostgreSQL table (`jobs`) with the following lifecycle:

```
PENDING → RUNNING → SUCCEEDED
                  ↘ PENDING (retry with exponential back-off)
                  ↘ FAILED (max attempts reached)
```

Workers use `SELECT … FOR UPDATE SKIP LOCKED` to claim jobs, enabling multiple workers to run in parallel safely.

Back-off delay formula: `base_delay_seconds × 2^(attempts-1)` (default base: 60 s).

## Handlers

| Job Type | Module | Description |
|---|---|---|
| `financial_analysis` | `app.worker.handlers.financial_analysis` | Aggregates sales, purchases, low stock, top customers |
| `pdf_report` | `app.worker.handlers.pdf_report` | Generates PDF using `reportlab`, stores Base64 in `job.result` |
| `bulk_inventory_update` | `app.worker.handlers.bulk_inventory` | Applies quantity deltas with row locks and strict validation |
